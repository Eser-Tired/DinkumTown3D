# v1.2.0：手机端操控重做——浮动摇杆与精简界面

本版本集中改造移动端触控：摇杆从"固定圆心"改为"按哪出哪"，屏幕上常驻按钮从 17 个减到 11 个。Windows 包同步更新，桌面端操作方式完全不变。

## 下载与安装

| 附件 | 平台 | 大小 |
|---|---|---|
| `DinkumTown3D-Windows-x64.exe` | Windows 10/11 x64 | 约 150.8 MiB |
| `DinkumTown3D-Android.apk` | arm64-v8a / x86_64 | 约 96.6 MiB |
| `SHA256SUMS.txt` | SHA-256 校验值 | 文本 |
| `BUILD_INFO.json` | 源码提交、签名指纹及验收记录 | JSON |

- Windows：下载 EXE 后直接双击，资源已经内嵌。EXE 未做商业代码签名，首次运行可能出现 SmartScreen 提示。
- 安卓：允许浏览器 / 文件管理器安装未知应用，再安装 APK；横屏游玩。使用 Mobile/Vulkan 渲染器，建议 Android 9 及以上、兼容 Vulkan 的 64 位设备。此要求参考 [Godot 官方硬件说明](https://docs.godotengine.org/en/stable/about/system_requirements.html)，手机帧率尚未实测。
- **升级说明：** 沿用 v1.1.0 的发布密钥，versionCode 从 2 升到 3，可直接覆盖安装、保留存档。从 v1.0.0 升级仍需先卸载（v1.0.0 密钥已丢失）。
- 校验文件：PowerShell 中执行 `Get-FileHash 文件路径 -Algorithm SHA256`，与 `SHA256SUMS.txt` 对照。

## 本版内容

### 摇杆：从"找圆心"改为"按哪出哪"

旧版摇杆固定在左下角，只有在它那个圆里按下才算数。手机横屏两手握持时，拇指的自然落点在屏幕中间偏下，离左下角很远，实际玩起来经常"推了个空"。

- 手指落在**屏幕左半边**任意位置，摇杆就在该处生成。
- 圆心在这一次按下期间**不会自己移动**，直到手指离开屏幕。
- 推杆量始终相对**落指处**计算，不是相对圆心——贴着屏幕边缘按下时摇杆会被裁掉一角，但不会凭空冒出一个方向。
- 松手后摇杆回到左下角静止位，下一次落指再浮到新位置。
- 左半屏整块是移动区，轻点交互（采集 / 攻击）移到右半屏；摇杆静止位固定，不再需要手动调整位置，设置里的"重置摇杆位置"一并移除。

### 界面：常驻按钮 17 → 11

| 处理 | 按钮 | 原因 |
|---|---|---|
| 删除 | 放置 | 建造模式下「使用」键本来就是放置，两个入口完全重复 |
| 删除 | 读 | 暂停菜单已有「读取存档」 |
| 删除 | 静音 | 设置面板的音量滑块拖到 0 即为静音 |
| 移入菜单 | 加速时间 | 低频操作，不值得长期占住右上角 |
| 按模式显示 | 旋转 | 只在建造模式出现 |
| 按模式显示 | 潜 | 只在水里出现 |

「存」保留在屏幕上：手机随时可能被电话或切后台打断，一键存档必须可达。

### 修复

- 建造模式的状态没有同步给触控层，导致「旋转」键从不出现，且建造时单指拖动被误当成转视角——建造预览无法挪动。改为走统一的模式切换入口。
- 建造模式的屏幕提示原本写"点「放置」确认"，与精简后的界面不符，已改为"点「使用」确认"。

## 验收与限制

| 项目 | 结果 |
|---|---|
| 战斗 / 水域 | 102 / 38 项，fails=0 |
| 存读档往返 | fails=0 |
| 触控 8 种分辨率 | 全部 bad=0（含新增的浮动摇杆与模式键断言） |
| 浮动摇杆断言 | 左半屏捕获、落指瞬间零位移、拖动期间圆心不动、松手归零并回静止位、左半屏按钮优先、右半屏不被抢占 |
| 模式键断言 | 默认隐藏、开建造 / 入水才显示、显示后不压住其他按钮 |
| Windows EXE | 实际启动通过 |
| APK | Release 模板；v2 / v3 签名验证通过，两个 64 位 ABI 均存在 |

仍然**没有连接安卓真机**，因此未完成安卓安装、真机画面、性能、发热与触控实机验收。浮动摇杆的手感结论来自逻辑断言与 Windows 上的截图检查，最终手感需要真机确认。部分逻辑自检仍有退出时 ObjectDB 清理警告。
